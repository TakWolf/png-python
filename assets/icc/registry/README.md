# ICC registered signature snapshots

The CMM, manufacturer, and device CSV files were retrieved from the
[official ICC registry](https://registry.color.org/) on 2026-11-16. Only the
signature columns were selected; contact information was omitted. `SOURCE.json`
records the download URLs, original download SHA-256 digests, selected data
SHA-256 digests, and record counts. ICC data is copyrighted by the International
Color Consortium; these snapshots contain only registration identifiers.

`tools/generate_icc_registry.py` generates pure Python lookup tables for offline
use. Device columns preserve the original `text-hexadecimal` representation;
incomplete or inconsistent upstream encodings are not automatically repaired.
Ambiguous entries are recorded separately. Unconfirmed signatures raise
`PngUnsupportedError`; absence from a snapshot does not prove that a signature
was never registered. To update the snapshots, select the same CSV columns,
update the provenance and digests, and regenerate the tables.

Regenerate the tables from the project root with the following command. The
script uses Ruff from the development dependencies to format the output
according to `pyproject.toml`:

```shell
uv run -m tools.generate_icc_registry
```

ICC.1:2022 sections 7.2.3, 7.2.12, and 7.2.13 require nonzero CMM, manufacturer,
and model signatures to be registered. Section 7.2.17 recommends registration
for the creator signature, so an unregistered creator does not cause rejection.
Checking a snapshot does not prove that a profile describes a real device or
was actually generated by the named manufacturer.

`characterization.json` contains the 56 reference names selected from the CMYK
Characterization Data table on the same date, for checking `ICCHDAT` references.
Internal spaces and letter case are preserved. The same provenance file records
the original page and selected data digests.
